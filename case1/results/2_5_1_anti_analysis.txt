1. THE CHECK, STATICALLY
--------------------------------------------------------------------------
  LSASS.Models.Enviornment::isVM, rva 0x2a34, is a short-circuit OR:
      DetectVM -> DetectVM2 -> DetectVM3 -> GetProcessorID
               -> CoreCount -> CpuTemp -> MatchMacAdd
  any one true and the method returns true.   [static]

      DetectVM         registry: SOFTWARE\Microsoft\Virtual Machine\Guest\Parameters -> HostName, VirtualMachineName
      DetectVM2        WMI: select * from Win32_BIOS -> version, SerialNumber; matches VMware / Virtual / XEN / Xen / 'A M I'
      DetectVM3        WMI: Win32_ComputerSystem -> Manufacturer, Model
      GetProcessorID   WMI: Win32_Processor -> ProcessorId
      CoreCount        processor count below a threshold
      CpuTemp          WMI thermal zone temperature (absent on most hypervisors)
      MatchMacAdd      NIC MAC prefix against known hypervisor OUIs

  Call sites of isVM in the assembly: 1   [static]
      LSASS.Core.Jobs::SystemSettings, IL 0x0045. The CIL that follows
      is not a branch around a payload -- it is string construction:

        0045  call  isVM
        004C  ldstr "Application running in VB/VM, host : "
        0053  call  VirtualMachine::get_Host
        0058  ldstr " and machine name : "
        005F  call  VirtualMachine::get_MachineName
        0064  call  System.String::Concat
        006C  ldstr "No VB/VM detected"

      and the result becomes the beacon's VMNOTES field. There is no
      exit, no sleep and no branch that skips the payload.  [static]

  `LSASS.Models.VirtualMachine` is a data model carrying Host and
  MachineName for that message -- it is not the check.  [static]

--------------------------------------------------------------------------
A NOTE ON WHY THE UNFORCED ARM ALREADY SEES BOTH SIDES
--------------------------------------------------------------------------
  Each probe ends in WMI, registry or NIC calls that this analysis
  models rather than performs, and those models return unconstrained
  values. Every `brtrue` in the OR chain therefore forks, so both
  outcomes of the check are explored without forcing anything. Forcing
  is still worth doing -- it is what makes the two outcomes separately
  attributable -- but it is not what makes them reachable.  [symbolic]
